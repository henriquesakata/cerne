## External sources (provenance)

The moment an external source (article, RFC, vendor/API doc, spec) **shapes** a feature, decision, or fix, register it — as you use it, **without waiting to be asked** — instead of leaving a bare URL in prose. Register **only the sources that actually informed the outcome**: a dead-end you opened and discarded is not a reference. If a URL is worth citing in the doc it is worth a `cerne reference`; if it is not, don't leave it as bare prose either.

```
cerne reference new "<title>" --url <url> --informs F-NNNN,D-NNNN [--facet <f>] [--component <c>] [--file <summary> | stdin]
```

It is marked external, its content is indexed (so `cerne ask` cites it), and `--informs` backlinks it to the entity it motivated.

References carry the **same two tag axes as notes** — `--facet` (the closed `infra`/`code`/`data`/`process`/`auth` set; an invalid facet aborts before any write) and `--component` (open, slug-normalized) — and they fold into the FTS the same way, so `cerne search`/`ask` find a reference by its tag. List and filter them with `cerne reference list [--facet <f>] [--component <c>] [--all] [--json]` — the **only** listing for references (AND across axes; `--all` includes superseded; `--json` for machine reads). Legacy references predate tags, so a `--facet` filter over them returns empty with a guidance message. Re-tag a reference in place, in any state (an obsolete one too), with `cerne reference retag R-NNNN --facet <f> --component <c>` (like notes/decisions) — it sets only the axis you pass (`--facet ""` clears that axis), preserves url/informs/body, and never makes the reference obsolete. Retire one with **`cerne reference retire R-NNNN --reason "…"`** (reason required) — a duplicate or a source that no longer holds moves from `current` to `obsolete`, leaving the current state but staying reachable via `reference list --all` and search as history; once it is obsolete, a new reference with the same URL can be registered. Source → idea → feature (F-0389): `--informs I-…` ties a source to an idea, `idea promote` carries the link to the new feature (keeping the `I-`), and `cerne reference link R-… --informs F-… [--unlink <ids>]` adds or removes targets later; `cerne show I-…` lists the sources.

**Does the source still stand?** `cerne reference check [R-…]` requests the URL of each current external reference (or only the ids given) and records the date, the HTTP status and a hash of the visible text; with the archive below it is the only command that touches the network, and it sends just the URL with a generic `cerne/<version>` User-Agent. The first check writes the baseline and flags nothing. After that each line is `ok`; `changed` (the text differs from the baseline: read the page, then confirm with `cerne reference keep R-NNNN`, which makes the current page the new baseline); `gone` (404, 410 or a domain that no longer exists); or `transient` (timeout, 5xx, 429, 403 or any other failure: the previous state is untouched). `changed` and `gone` list the entities the source informs, so you know which decision to review. `cerne lint` flags a `gone` reference as the blocking `reference-gone`, reading only the recorded check and never the network; fix it with `cerne reference retire R-NNNN --reason "source gone"` or check again if the page came back. `changed` is never a lint finding.

**Keep a dated copy of the page.** With `references.archive` on, `cerne reference new` sends the source's URL to the Wayback Machine of the Internet Archive and records the link and date of the copy, the one nearest the day the source was registered: `existing` (the archive already holds a capture nearer that day than today, or Save Page Now refused and that capture was taken) or `saved` (a new copy). With the setting on, `reference new` therefore uses the network (so do `reference check` and `reference archive`; lint, pull and push never do). A failure leaves the reference registered with its archive `pending`. `cerne reference archive [R-…]` does the same for every current external reference with no copy yet or a pending one (or only the ids given), one line each and the counts. The setting is off by default and human-only: the owner turns it on in the Settings screen of `cerne ui`; an agent never does. Only the URL is sent, never the title, summary, informs, ids or project name, and only for a page that answers 200 to an anonymous GET. Nothing is sent for an internal host (`localhost`, `.local`, a private or loopback IP, a name with no dot or a reserved suffix such as `.internal` or `.corp`), an `unregistered_source_ignore` item, a share-link host (Google Docs, Drive and Photos, SharePoint, OneDrive, Dropbox, Box, Gist, Notion, Figma, Loom, Slack, Teams, ChatGPT and Claude shares, Pastebin, Canva, Miro, HackMD, ngrok and Cloudflare tunnels), a URL with credentials or a secret parameter (`token`, `key`, `secret`, `sig`, `signature`, `auth`, `password`, `access_token`, a JWT value, a mail-tracking id, a Discord or Telegram webhook path), a name that resolves to a private address, or a page an anonymous GET does not read with a final 200 (401, 403, 404 or a login page: `not public`). `cerne reference new … --no-archive` keeps a source from ever being sent, now or later, and so does every reference with the same URL; `cerne reference archive --opt-out R-…` does it for a reference that already exists (it needs ids and reaches no network). Public means only that the page answers 200 to an anonymous GET: a private page reachable by its link on an unlisted host still passes. So run `cerne reference archive --dry-run` before the first real run and read the list: it makes every check and lists what would be sent, sending nothing to the archive service. `cerne show R-NNNN`, `cerne reference list` and the `gone` and `changed` lines of `reference check` show the copy's link.

A reference keeps the source, not the project's guidance. When a note rests on the source, link them (`--informs N-NNNN`, or `cerne reference link R-NNNN --informs N-NNNN`); see `notes-and-knowledge.md`. Mistake: guidance written in a reference. Its summary says what the source claims; what to do here goes in a note.
